# 真机调试与上线部署（视频 / AI 识别）

> 结论先说：**真机上 `127.0.0.1` 指的是手机自己，不是你的电脑。**
> 所以只要没有公网地址，真机上的 AI 识别和团队视频一定连不上。
> 要让别人扫码体验，必须把 `serve_fusion.py` 部署到一个手机能访问的
> **HTTPS 地址**，并在微信公众平台登记合法域名。

---

## 一、为什么现在真机不能用

| 现象 | 原因 |
| --- | --- |
| AI 显示“未连接评估服务器” | 手机访问不到 `127.0.0.1:8000`；`config.js` 里的局域网 IP 也不是手机当前能访问的地址 |
| AI 显示“内置演示结果” | 旧版本在服务连不上时自动降级到 mock；现在 `AI_FALLBACK_TO_DEMO: false`，会明确报错而不是冒充识别成功 |
| 团队视频打不开 | 视频也由同一个后端提供（`/video/team.mp4`），后端连不上自然打不开 |
| 电脑 / 开发者工具正常 | 电脑和 Python 服务在同一台机器上，`127.0.0.1` 能通 |

---

## 二、路线 A：临时真机调试（电脑保持开机）

适合自己用手机测试，不适合正式发布。

### 1. 启动服务

在项目根目录执行：

```powershell
cd ai-service\scripts
python serve_fusion.py --host 0.0.0.0 --port 8000
```

等控制台出现 `Uvicorn running on http://0.0.0.0:8000`。
浏览器打开 `http://127.0.0.1:8000/health`，应返回 `"status":"ok"`。

### 2. 让手机能访问

**方式一：同一 Wi-Fi（最快）**

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

假设电脑 IP 是 `192.168.1.10`，真机调试时服务地址填：

```text
http://192.168.1.10:8000
```

还要确保：

- 手机和电脑连同一个 Wi-Fi；
- Windows 防火墙放行 8000；
- 服务监听的是 `0.0.0.0`，不是 `127.0.0.1`。

管理员 PowerShell 放行一次：

```powershell
New-NetFirewallRule -DisplayName "Coral Guardian 8000" `
  -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

**方式二：Cloudflare Tunnel（不同网络也能测，自带 HTTPS）**

电脑安装 `cloudflared` 后执行：

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
```

命令会输出一个 `https://xxxx.trycloudflare.com` 地址。
这个地址只适合临时测试，电脑或隧道进程关闭就失效，也不建议用于正式审核。

### 3. 在小程序里填地址

打开小程序「我的」→ 右上角 ⚙ → 填写上面的地址 → 「保存并测试」。

地址会存到本机 `coral_api_base`，AI 识别和团队视频会立即使用它。
清空输入框并确认可恢复自动探测。

> 开发者工具真机调试时，还需要在「详情 → 本地设置」勾选
> **不校验合法域名、web-view、TLS 版本以及 HTTPS 证书**。
> 这只对调试有效，**不能代替正式域名配置**。

## 三、路线 B：正式上线（别人扫码也能用）

正式版必须满足：

1. 后端部署在公网服务器，7×24 在线；
2. 使用 HTTPS 域名（国内服务器通常还需 ICP 备案）；
3. 微信公众平台登记域名；
4. `config.js` 填入同一个公网地址；
5. 重新上传代码并提交审核。

### 1. 部署 FastAPI 服务

服务器建议：Ubuntu 22.04+、4 核 8 GB 起；CPU 推理约 5–10 秒/张，有 NVIDIA 显卡更快。

```bash
cd /opt
git clone https://github.com/starhaohanwuyin/blue-coral-guardian.git
cd blue-coral-guardian/ai-service
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 放入 weights/ 与 data/noaa/（见创建者部署指南）
cd scripts
python serve_fusion.py --host 127.0.0.1 --port 8000
```

服务只监听 `127.0.0.1`，由 Nginx 对外提供 HTTPS。

**也可以直接用 Docker Compose**（在 `ai-service/deploy` 下）：

```bash
cd ai-service/deploy
CORAL_API_TOKEN=你的随机串 docker compose up -d --build
curl http://127.0.0.1:8000/health
```

`docker-compose.yml` 会把 `weights/`、`data/`、`reports/` 挂载进容器，
并把端口只绑定到 `127.0.0.1:8000`，公网入口仍然交给 Nginx。

**不用 Docker 时**，仓库也提供了 `ai-service/deploy/coral-api.service`：

```bash
sudo cp ai-service/deploy/coral-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now coral-api
sudo systemctl status coral-api
```

注意把 unit 文件里的 `/opt/blue-coral-guardian` 改成你的实际项目路径。

### 2. Nginx + HTTPS

> 下面是 **coralguard.cn 的完整单站点配置示例**。
> 关键点：原有网页继续由 `location /` 提供；只有 `/api/` 转发给 FastAPI。
> 如果你的现有站点是静态目录，把 `root` 改成现有目录；如果现有站点本身是
> 反向代理，保留你原来的 `location /` 内容即可。

`/etc/nginx/sites-available/coralguard.cn`：

```nginx
# HTTP：只负责跳转到 HTTPS（证书申请前可先保留这段）
server {
    listen 80;
    server_name coralguard.cn;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

# HTTPS：原有网页 + FastAPI 后端
server {
    listen 443 ssl http2;
    server_name coralguard.cn;

    ssl_certificate     /etc/letsencrypt/live/coralguard.cn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/coralguard.cn/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # AI 图片上传，默认 1MB 会 413
    client_max_body_size 25m;

    # ===== 原有网页：保持你现在的站点配置 =====
    location / {
        # 静态站点示例；如果现有网页是反向代理，请换成原来的 proxy_pass
        root /var/www/coralguard.cn;
        index index.html index.htm;
        try_files $uri $uri/ /index.html;
    }

    # ===== FastAPI 后端：/api/ → 127.0.0.1:8000/ =====
    # ⚠️ proxy_pass 末尾的 "/" 不能少：
    #   /api/health  → 127.0.0.1:8000/health
    #   /api/analyze → 127.0.0.1:8000/analyze
    #   /api/video/team.mp4 → 127.0.0.1:8000/video/team.mp4
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout 180s;
        proxy_send_timeout 180s;

        # 视频 Range 请求原样转发
        proxy_set_header Range $http_range;
        proxy_set_header If-Range $http_if_range;
        proxy_buffering off;
    }

}
```

> 如果你的现有站点已经配置了 443/证书，**不要新建第二个同名 server 块**；
> 只要把 `location /api/ { ... }` 这一段加进现有 443 server 块即可。
> 如果你原来的 `location /` 是 `proxy_pass`，不要换成上面的静态 root。

> **证书还不存在时**：先只保留上面的 80 端口 server 块（并把 `location /`
> 改成你现有站点的配置），执行 `certbot certonly --webroot ...` 申请证书；
> 证书生成后再启用 443 的 server 块。否则 `nginx -t` 会因为找不到
> `/etc/letsencrypt/live/coralguard.cn/` 下的证书文件而失败。

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/coralguard.cn /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

首次申请证书（如果还没有证书）：

```bash
sudo mkdir -p /var/www/certbot
sudo certbot certonly --webroot -w /var/www/certbot -d coralguard.cn
sudo nginx -t && sudo systemctl reload nginx
```

验证：

```bash
# 原有网页仍然正常
curl -I https://coralguard.cn/

# FastAPI 健康检查
curl https://coralguard.cn/api/health
```

应返回 `"status":"ok"`。

### 3. 配置小程序公网地址

修改 `miniprogram/utils/config.js`：

```js
const PUBLIC_API_BASE = 'https://coralguard.cn/api'
```

**必须带 `/api`**：代码会在这个地址后追加 `/health`、`/analyze`、
`/video/team.mp4`、`/mp/assets/img/...`，Nginx 再去掉 `/api/` 前缀转给
FastAPI。填成 `https://coralguard.cn` 会打到原有网页，AI 仍然连不上。

不要再让普通用户手动填地址；重新编译后，真机默认就连公网服务。

### 4. 微信公众平台登记域名

登录 [微信公众平台](https://mp.weixin.qq.com/) → 开发管理 → 开发设置 → 服务器域名：

| 类型 | 填写 |
| --- | --- |
| request 合法域名 | `https://coralguard.cn` |
| uploadFile 合法域名 | `https://coralguard.cn` |
| downloadFile 合法域名 | `https://coralguard.cn` |

微信后台只填域名，**不要填 `/api` 路径**。团队视频、珊瑚图片也走同一个域名，
因此 `downloadFile` 必须登记。若使用 `www.coralguard.cn`，把 www 也一起登记。

### 5. 隐私与能力声明

在公众平台补齐：

- 用户隐私保护指引：相机/相册（上传珊瑚照片）、位置信息（可选）、图片识别用途；
- `app.json` 已声明 `getLocation`，后台仍需声明位置用途；
- 若启用 AI 上传，说明图片会发送到你的评估服务器做识别。

### 6. 上传与真机验收

1. 开发者工具「上传」→ 版本号 / 备注；
2. 公众平台提交审核；
3. 用**体验版**在 4G/5G（不连电脑 Wi-Fi）下测试：
   - AI 上传后不再出现「演示数据」；
   - 团队视频能播放；
   - 珊瑚图鉴图片能加载；
   - 证书能保存/预览。

## 四、部署安全检查

- 公网部署建议设置 `CORAL_API_TOKEN`，并在 `config.js` 填入同一个值；
  Token 在客户端可被提取，主要作用是挡住随意调用，不能当成真正的秘密。
- 保持默认限流（`CORAL_RATE_LIMIT=60`，每 IP 每分钟）。
- 不要把图鉴写接口暴露给公网；默认策略已经限制本机写入。
- 用 `systemd`、Docker Compose 或云平台进程守护，保证服务崩溃后自动重启。

## 五、常见问题

| 现象 | 排查 |
| --- | --- |
| 真机仍显示未连接 | 手机浏览器能否打开 `https://api.example.com/health`？4G 下能否打开？ |
| 开发者工具能通、真机不能 | 开发者工具与真机用的不是同一个地址；检查 `PUBLIC_API_BASE` / 手动设置 |
| 上传报“不合法域名” | 公众平台 request/uploadFile 域名未登记，且调试时未勾选“不校验合法域名” |
| 视频能加载但 AI 不能 | 检查 `/analyze` 是否 200；AI 还需要 uploadFile 域名 |
| 上传大图 413 | Nginx `client_max_body_size 25m` |
| AI 很慢 | CPU 推理正常 5–10 秒；首次启动加载模型还要 40–90 秒 |

## 六、当前代码约定

- 正式地址：`miniprogram/utils/config.js` 的 `PUBLIC_API_BASE`；
- 临时覆盖：小程序「我的 → ⚙」写入本机 storage；
- AI 连不上：默认报错，不再自动返回演示数据；
- 视频 / 图鉴图片：与 AI 共用同一个服务地址。
