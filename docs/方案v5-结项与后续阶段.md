## 二、下一阶段的候选方向

> 按「**技术可解性 × 答辩价值**」排序。每条都标注了根因、成本与验收标准。

### 🥇 P1 · 印太域白化召回（**唯一有明确技术根因的遗留问题**）

**现状**：白化分类模型在第三方新域召回 **96.77%**、原域 **88.78%**，
但在**印太域（印尼 CORAL_INDO）仅 42.31%**。

**根因（已定位）**：**判别边界跨域错位** ——
模型学到的是"颜色偏移 + 纹理"的组合判别，
而印太域的拍摄白平衡、水体色偏与训练域不同，
导致健康样本被推过判别边界（假阳性），白化真样本反而落在边界内侧。

**可选做法**（按性价比排序）：

| 做法 | 成本 | 预期 | 风险 |
|---|---|---|---|
| **A. 按域后验校正**（用少量目标域样本估计先验偏移）| 2–3 h | 召回可升至 60–75% | 需目标域少量标注 |
| **B. 温度标定 + 阈值按域重调** | 1–2 h | 中等 | 治标 |
| **C. 域对抗训练（DANN）** | 1–2 天 | 较彻底 | 训练不稳定 |
| **D. 少量目标域样本微调** | 3–4 h | 最有效 | 需标注数据 |

**验收标准**：印太域白化召回 ≥ 65%，且原域与新域召回**下降不超过 2 pt**。

> ⚠️ 注意：本项目已在 `docs/评估方法与局限.md` 中声明该指标，
> **改善后需同步更新该文档与报告，不得只报好消息。**

### 🥈 P2 · 真实劣化照片验证（**方法学补强**）

**现状**：使用边界结论（≤8m / ≥15m）**全部基于合成降质**
（`degrade_underwater.py` 的物理模型），**未用真实不同深度的照片验证**。

**为什么重要**：合成降质是我方构造的，用它验证自己的结论存在**循环论证风险**。
（已在报告中声明该局限）

**做法**：
1. 采集同一礁区**不同深度**（3m / 8m / 15m）的真实照片
2. 用模型估计覆盖率，与同点位实地样方对比
3. 检验失效深度是否与合成实验一致

**成本**：取决于能否采集到照片（**这是主要瓶颈，非计算成本**）

**验收标准**：真实照片上的失效深度与合成实验一致（±3m 内）。

### 🥉 P3 · YOLOv9 珊瑚个体计数（**能力扩展**）· ✅ **已完成 2026-10-10**

**背景**：原方案点名的 YOLOv9 未用于覆盖率管线（理由见 `docs/技术选型偏差说明.md`）；
P3 把它补做在**附加能力**上（不替换现有分割）。

**新增输出**：珊瑚**个体数量**与位置 —— 这是覆盖率之外的独立信息。

**做法**：
1. 从 Coralscapes 像素掩膜提取连通域 → 转目标框
2. 用 `ultralytics` 训练 YOLOv9c 检测器（单类 `coral`，imgsz 640 / batch 8 / 50 epochs）
3. 与现有分割**并行**输出（`/analyze` 新增 `coralCount`，另加 `POST /count`）

**实际结果**：官方 validation split（166 张）**mAP@0.5 = 0.4217**（验收线 0.35），
训练集为官方 train split **全 9 分片**（1517 张 / 32976 框）；
**现有分割 mIoU 未下降**（0.5484 → 0.5484），服务既有输出**逐键未变**。

**成本**：实际约 5.5 h（R0 640 从零 146 min + R1 896 微调 156 min，含数据下载与提取）　**验收标准**：mAP@0.5 ≥ 0.35 ✅、不影响现有分割 ✅

> 详见《项目交接与续接指引》**§7**（含真值为「自动标注」的局限声明）。

### P4 · 热压力与白化的时序因果分析

**现状**：气候数据与图像结果只是**并列展示**，未建模**滞后效应**。

**科学问题**：DHW 峰值后**多久**才出现白化？滞后几周？

**做法**：
1. 对齐 NOAA 月度 DHW 与照片拍摄日期
2. 估计滞后相关系数 / 滞后窗口
3. 把「滞后修正」纳入风险预判

**成本**：4–6 h（**前提：照片需有拍摄日期**，当前 iNat 元数据可能不全）

### P5 · 移动端 / 离线部署

**现状**：需要 PC 运行 Python 服务；小程序通过 `http://127.0.0.1:8000` 访问。

**可选**：
- 模型量化（INT8）+ ONNX Runtime → 端侧推理
- 或部署到有公网 IP 的服务器 + HTTPS 域名（小程序正式版**必须** HTTPS 已备案域名）

**成本**：量化 1 天；服务器部署 0.5 天　**这是小程序正式上线的必要前提**

## 三、不建议再投入的方向（已论证）

| 方向 | 不做的理由 |
|---|---|
| **完全重做为 YOLO+SAM 管线** | 现有方案有实测背书（mIoU 0.548、星地 0.15 pt）；重做风险高收益存疑 |
| **三模型集成** | 依赖已排除的许可证不明权重；"+2–4 点"为预估非实测 |
| **人类基线** | 经确认无法组织标注，已列为**永久局限** |
| **站点级覆盖率排序** | 根因是 iNat 照片非等距样方（摄影师选拍主体），非模型问题；需标准化采样才能解决 |
