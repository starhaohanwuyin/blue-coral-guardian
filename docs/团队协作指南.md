# 团队协作指南（多人开发一个小程序怎么合并代码）

> 面向不熟悉 Git 的同学。看完这一篇，你就知道"多个开发者怎么把代码合到一起"。

---

## 一、先理解核心思路（30 秒）

多人合并代码，本质只有一句话：

> **大家不要各自在自己电脑上改同一份互不相干的副本，而是共用「一个远程仓库」当唯一真相。**

```
        GitHub / Gitee 远程仓库（云端，唯一的"正版"）
                    ↑ ↓
       ┌────────────┼────────────┐
    你的电脑      队友A的电脑     队友B的电脑
   （本地副本）   （本地副本）    （本地副本）
```

流程永远是这 3 步循环：

```
pull（拉最新） → 改代码 → commit + push（推上去） → 合并
```

**只要每次动手前先 `pull`，就不会出现"代码被覆盖"的事故。**

---

## 二、一次性准备（组长做一次）

### 1. 建远程仓库

到 GitHub 或 Gitee 新建仓库（建议选 **私有 Private**，作业别公开）：

- 仓库名：`blue_coral`
- **不要**勾选 "Add a README"（本地已经有代码了，勾了反而要处理冲突）

### 2. 把本地代码推上去

在本项目目录（`blue_coral`）打开终端，依次执行：

```bash
git init -b main                        # 初始化本地仓库，主分支叫 main
git add -A                              # 把所有文件加入暂存区
git commit -m "chore: 初始化蓝珊小程序项目"   # 首次提交
git remote add origin <仓库地址>          # 关联远程仓库，地址从网页复制
git push -u origin main                 # 推送到远程
```

> `<仓库地址>` 形如 `https://github.com/你的用户名/blue_coral.git`。
> 第一次 push 会要求登录：GitHub 用 **Personal Access Token**（不是密码），Gitee 用账号密码即可。

### 3. 把队友加进仓库

仓库网页 → Settings → Collaborators（GitHub）/ 仓库成员管理（Gitee）→ 添加队友账号。

### 4. 微信平台侧也要加人（这一步很多人忘）

到 [微信公众平台](https://mp.weixin.qq.com) → **管理 → 成员管理 → 项目成员**，把队友的**微信号**加为「开发者」。

- 不加的话，队友**能改代码但无法上传/预览**。
- 上传代码的权限只有「开发者」及以上才有。

## 三、每个队友（包括你）第一次要做的事

```bash
git clone <仓库地址>        # 把仓库下载到自己电脑
cd blue_coral
```

然后用微信开发者工具「导入项目」，目录选这个文件夹即可。
（`project.private.config.json` 不在仓库里，工具会自动生成一份 —— **这是正常的**。）

最后配置一下自己的身份（只做一次）：

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"
```

## 四、日常开发循环（最重要的部分）

### 1️⃣ 动手前，先拉最新代码

```bash
git pull
```

> 这一步不能省。跳过它就是 90% 冲突的根源。

### 2️⃣ 建自己的分支再改

不要所有人直接在 `main` 上改。每人开自己的分支：

```bash
git checkout -b feature/张三-认养页      # 分支名建议带姓名，一眼看出是谁的
```

### 3️⃣ 改完代码，提交

```bash
git status                    # 看看改了哪些文件
git add -A                    # 全部加入
git commit -m "feat: 完成认养页喂养弹窗"    # 写清楚做了什么
```

提交信息建议统一格式（方便回溯）：

| 前缀 | 含义 |
| --- | --- |
| `feat:` | 新功能 |
| `fix:` | 修 bug |
| `style:` | 只改样式 |
| `docs:` | 只改文档 |
| `refactor:` | 重构，不改功能 |

### 4️⃣ 推送到远程

```bash
git push -u origin feature/张三-认养页
```

### 5️⃣ 合并进 main

两种方式，选一种：

**方式 A：Pull Request（推荐，适合有 review）**

到 GitHub/Gitee 网页上，会看到 "Compare & pull request" 按钮 → 创建 PR → 组长点 **Merge**。

**方式 B：本地直接合并（人少、图省事）**

```bash
git checkout main
git pull                          # 先确保 main 是最新的
git merge feature/张三-认养页      # 把你的分支合进来
git push                          # 推上去
```

合并完，别人只要 `git pull`，就拿到你的代码了 —— **这就是"整合代码"**。

## 五、冲突了怎么办？（一定会遇到，别慌）

冲突 = 你和别人**改了同一个文件的同一行**。Git 不会自己决定用谁的，需要在文件里手动选。

冲突时文件里会出现这种标记：

```js
<<<<<<< HEAD
this.setData({ growth: 65 })      ← 你本地的版本
=======
this.setData({ growth: 70 })      ← 别人的版本
>>>>>>> feature/张三-认养页
```

**处理步骤：**

1. 打开冲突文件，删掉 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记；
2. 在里面留下**正确的那一行**（或把两者合成一行）；
3. 然后：

```bash
git add 冲突的文件
git commit -m "fix: 解决认养页成长值冲突"
```

> 实在搞不定：`git merge --abort` 可以**放弃这次合并**，回到合并前的状态，重新来过。

## 六、小程序项目专属的注意事项 ⚠️

这是本项目最容易踩的坑，务必看：

| 文件 | 要不要提交 | 原因 |
| --- | --- | --- |
| `project.private.config.json` | **绝对不要** | 每人的本机编译设置，IDE 打开就改写。已在 `.gitignore` 中排除 |
| `project.config.json` | **要** | 团队共享的工程配置（AppID、基础库版本等） |
| `app.json` | 要，但**它是"热点文件"** | 谁新增页面都要改它 → 最容易冲突。建议**新建页面统一由一个人加** |

**分工建议（重要）：**

- 22 个页面天然可分：一人负责一组页面（如 A 管首页+认养，B 管科普+AI识别，C 管商城+证书+勋章）；
- 每个页面是独立的一套 4 个文件，**只要不碰同一页，几乎不会冲突**；
- `utils/api.js`、`utils/config.js` 是公共文件，改动前在群里说一声，安排一个人改。

## 七、命令速查表

```bash
git pull                      # 拉取最新代码（每天开工第一件事）
git status                    # 看当前改了什么
git add -A                    # 暂存全部改动
git commit -m "feat: xxx"     # 提交
git push                      # 推送到远程
git checkout -b feature/名字   # 新建并切换到自己的分支
git checkout main             # 切回主分支
git merge feature/名字         # 把分支合并进 main
git log --oneline --graph     # 图形化看提交历史
git merge --abort             # 放弃本次合并
git restore 文件名             # 撤销某个文件未提交的修改
```

## 八、上传发布（代码合并完之后）

1. 到微信公众平台确认自己是该 AppID 的「开发者」；
2. 开发者工具右上角点 **「上传」**，填版本号（如 `1.0.0`）和描述；
3. 到公众平台 → **版本管理** → 把刚上传的版本设为「体验版」（给队友扫码测试）；
4. 测试没问题后 → **提交审核** → 审核通过后 **发布**。

> ⚠️ 注意：`project.config.json` 里的 AppID 必须是**你自己/团队有权限**的那个。
> 用别人的 AppID 上传会直接报「无权限」。
