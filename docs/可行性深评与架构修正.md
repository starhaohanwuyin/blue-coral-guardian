# 可行性深评与架构修正（第二轮）

> 上一轮我修正了「数据域错配」。这一轮我发现了**更根本的错误：任务框架本身错了**，
> 以及一个**会直接影响项目合法性的许可证冲突**。

---

## 一、我仍低估的 6 处（按严重程度，全部有证据）

### 🔴 1. 任务框架错了 —— 这是比数据域错配更根本的错误

**项目简介的原文要求**：
> 「精准区分活珊瑚、白化珊瑚、死亡珊瑚及海藻覆盖区域，**自动算出这片样方的珊瑚覆盖率和白化占比**」

**我此前做的是**：整图单标签分类（一张图 → 一个种类 + 一个白化标签）

**为什么这是错的**：
- 一张真实样方照片里有**几十株珊瑚**、**多个种类**、**不同的白化程度**
- 单标签分类**在数学上无法表达**"覆盖率 62%、白化占比 18%"
- 换句话说：**我做的模型回答不了项目最核心的那个问题**

**正确的任务**：**像素级语义分割**（每个像素判一类 → 统计各类占比）

**好消息**：这个任务有现成的权威方案——
| 资源 | 说明 |
|---|---|
| **Coralscapes 数据集** | EPFL 出品，**2075 图 / 1024×2048px / 39 个底栖类 / 174k 多边形标注**，**Apache-2.0** |
| **论文** | arXiv 2503.20000（*The Coralscapes Dataset: Semantic Scene Understanding in Coral Reefs*） |
| **现成模型** | 🤗 `EPFL-ECEO/segformer-b2-finetuned-coralscapes-1024-1024`（40 类，**已训练好，可直接推理**） |
| **配套代码** | `eceo-epfl/coralscapesScripts`（含 DeepLabV3+/SegFormer/DINOv2/UNet++ 共 11 套配置） |

> 这意味着**"覆盖率、白化占比"这一核心能力不需要从零训练**，可站在 EPFL 的成果上做。

### 🔴 2. 许可证与商业模式直接冲突（法律风险）

实测仙本那 1319 张照片的许可证：

| 许可证 | 条数 | 占比 | 能否商用 |
|---|---|---|---|
| **cc-by-nc** | 456 | **78%** | ❌ 禁止商业使用 |
| cc-by-sa | 107 | 18% | ✅ |
| none | 12 | 2% | ⚠ 未知 |
| cc-by-nc-nd | 7 | 1% | ❌ |
| cc-by | 3 | 1% | ✅ |
| cc-by-nc-sa | 2 | 0% | ❌ |

**项目简介明确写了商业模式**（面向保育部门/科研机构技术服务、面向潜水从业者工具、面向公众认养订阅）。
**用 CC-BY-NC 数据训练出来的模型去支撑商业服务，存在明确的侵权风险。**

→ 必须做**双轨数据策略**（见第四节）。

### 🔴 3. iNaturalist 测试集不代表野外实用条件

| 维度 | iNat 照片 | 实际使用场景 |
|---|---|---|
| 拍摄意图 | 潜水员**专门对着珊瑚拍** | 志愿者**顺手拍**整片礁区 |
| 距离/构图 | 近距离、主体居中、构图好 | 远距离、主体小、构图随意 |
| 光照 | 多数打潜水灯、能见度好 | 自然光、蓝绿偏、弱光 |
| 结果 | **精度必然偏乐观** | 真实条件更差 |

**更严重的：物种选择偏差**
- 仙本那 Observation Top5 是 Plerogyra(45)、Pocillopora(42)、Acropora(42)、Heliofungia(38)、Fimbriaphyllia(33)
- 这些是**大、显眼、好看、易鉴定**的珊瑚
- **稀有、小型、隐蔽种几乎完全缺失** → 训练出的类别分布 ≠ 真实礁区结构

### 🔴 4. 标签噪声决定精度天花板

- iNat「research grade」= 需 **2/3 鉴定者同意**
- 但存在**锚定效应**（第一个鉴定者的判断会带偏后续）
- 文献估计 RG 记录仍有 **5–10% 错误率**

→ **标签本身有 5–10% 噪声，模型不可能显著超过 90–95%**。这不是模型能力问题，是数据上限。

### 🟡 5. 「99.9%」这个口径被我过度使用

选择性预测算出的覆盖率只有 **3.1%–24.3%**。含义是：
- 覆盖率 3% → **97% 的照片要转人工复核 → 系统实际上不可用**
- 这个指标"数学上正确、工程上没意义"

**正确口径应该是**：报告「**固定覆盖率下的准确率**」，例如
> 「在 90% 覆盖率下准确率 95.2%；剩余 10% 低置信度样本转人工复核」

这才是一个保育工具该有的指标。

### 🟡 6. 近重复与非独立同分布

- iNat 上**同一张照片可能被多次上传**（不同观察、不同用户）
- 587 条观察**集中在少数潜点与少数日期**（潜水季）
- → 1319 张照片的**有效样本量远小于 1319**，指标置信区间比表面更宽

**必须做**：跨 train/test 的**感知哈希（pHash）去重**，否则就是泄漏。

## 二、修正后的系统架构（关键）

```
上传样方照片
      │
      ▼
┌─────────────────────────────────────────────┐
│ 【模型 A · 底栖语义分割】  ★回答"覆盖率/白化占比"│
│  起点：Coralscapes 预训练 SegFormer-B2（现成） │
│  输出：活珊瑚% / 白化% / 死亡% / 藻类% / 沙砾%  │
└─────────────────────────────────────────────┘
      │  取出「硬珊瑚」像素区域
      ▼
┌─────────────────────────────────────────────┐
│ 【模型 B · 珊瑚属分类】    ★回答"是什么珊瑚"    │
│  输入：从分割结果裁剪出的珊瑚主体小图           │
│  输出：属 + 置信度 + 拒识标记                   │
└─────────────────────────────────────────────┘
      │
      ▼
【融合】+ NOAA DHW 热压力 → 礁点修复优先级 → LLM 报告
```

**为什么这样拆是对的**：
1. **A 解决了项目最核心的量化需求**（覆盖率/白化占比），且**有现成模型可用**
2. **B 只需在 A 分割出的珊瑚像素上运行** → 输入更干净（背景已剔除、主体明确）→ **精度天然更高**
3. B 只需覆盖硬珊瑚属 → **数据需求更小、更聚焦**
4. 两者可独立迭代、独立评估、独立降级

**与项目简介的对齐度**：
| 简介原文 | 对应模块 |
|---|---|
| 「区分活珊瑚、白化珊瑚、死亡珊瑚及海藻覆盖区域」 | **模型 A**（分割） |
| 「自动算出这片样方的珊瑚覆盖率和白化占比」 | **模型 A**（像素统计） |
| 「识别是什么珊瑚」 | **模型 B**（属分类） |

## 三、指标口径修正

| 原口径 | 修正后 |
|---|---|
| 单吹「99.9%」 | **覆盖率–准确率曲线**：报告固定覆盖率（如 90%）下的准确率 |
| Top-1 准确率（裸值） | Top-1 + **Bootstrap 95% 置信区间** |
| — | **新增校准误差 ECE**（置信度是否可信） |
| — | **新增覆盖率误差**（预测占比 vs 真值占比的绝对差，分割任务的专属指标） |
| — | **新增近重复审计**（pHash 跨集去重后的复测） |

## 四、数据合规双轨策略

| 用途 | 允许数据 | 说明 |
|---|---|---|
| **商用模型** | CC0 / CC-BY / CC-BY-SA / **Apache-2.0** / 美国联邦政府作品 | Coralscapes ✅、NOAA CRW ✅、NOAA 太平洋底栖模型 ✅、iNat 非NC子集（110 条） |
| **研究/评估** | 可含 CC-BY-NC，但**必须标注非商业** | iNat 仙本那 456 条 NC |
| **对外发布** | 只发布非NC训练的模型 | 若必须用 NC 数据，需逐一联系作者取得授权 |

**⚠ 需要你确认：项目最终是否商业化？** 这决定整个数据策略。若确定商用，仙本那可用的实测数据只有 110 条，需要扩充其他合规来源。
