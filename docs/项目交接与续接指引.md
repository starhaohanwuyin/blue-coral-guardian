**关键耦合**：
- 小程序 ↔ `serve_fusion.py`（**不是** 已弃用的 `serve.py`）
- Skill ↔ `serve_fusion.py`（端点为 `/analyze`、`/climate`、`/priority`）
- `restoration_priority` 依赖 `climate_context` 与 `restoration_simulation`

**四个模型分别回答不同问题**（易混）：

| 模型 | 回答 | 注意 |
|---|---|---|
| Model A（分割）| 各类**像素占比** | 其白化像素跨域 **AUC 0.46 无效** |
| Model B 属分类 | 这是什么**珊瑚属** | 只在分割出的珊瑚主体上判 |
| Model B 白化分类 | 整图**白化状态** | **白化结论以它为准** |
| **Model C 个体检测** | **有多少个珊瑚个体、在哪** | **P3 附加能力**；与上面三者互不替代，缺失也不影响主结果 |

**为什么"修复优先级"没有准确率——是任务性质，不是技术没做到**：
"哪个点位该优先修复"是**价值判断，不存在客观 ground truth**，因此本项目**主动选择**
只报评分构成、权重与依据（可解释），不报准确率。这与"印太域白化做不出来"完全不同：
后者是**能力缺口**（召回仅 42.31%），前者是**指标口径选择**。

## 有条件交付（引用时必须带限定）

| 能力 | 限定 |
|---|---|
| 覆盖率 | 仅**区域尺度**；站点级不成立（3 站点 15 张，偏差 **+11.7 pt**，r = **−0.56**）|
| 覆盖率/白化 | 深度边界：≤8m 误差 ≤3 pt；**≥15m 完全失效**（−39.5 pt）|
| 属级 | 只到**属**不到**种**；长尾属弱；受 iNaturalist 采样偏置影响 |
| 个体计数 | 真值为**掩膜连通域自动标注**，紧贴个体合并 → 偏少；**跨域（仙本那实拍）未验证** |
| 拍摄条件闸门 | 阈值在**合成降质**集上标定；**真实劣化照片（P2）未验证** |
| 修复优先级 | **权重未经真实修复成效标定**；单点代表点位；未纳入社会经济因子 |
| **环境数据（气候背景）** | ①**只覆盖仙本那网格** 4.025–5.025°N × 118.025–119.525°E —— **网格外直接返回 `ok=false`**，不给"最近格点"的值（旧版会静默取，实测查深圳会报出仙本那的"严重热应激"，已修，见 §9.8 #38）；②**2023–2025 历史值，不是实时预警**，不能回答"现在热压力多少"；③**站点级不成立**（卫星 5km ≠ 站点，仅事件级一致，n=4）；④引用"DHW 峰值"**必须标空间单位**（查询格点 5.42 / 核心区 10.03 / 网格最大 14.87）|
| **综合研判 + 10 年模拟** | 规则启发式：**不报准确率是口径选择，不是能力缺失**；但**模拟为示意性推演**，未做本地参数标定，不得当预测用；气候维度缺失时会如实标 `climateAvailable=false` 且不参与打分 |
| **投放时间窗建议** | ①**只是热压力一个维度**，不含底质/水深/水流/藻类/草食动物/人力管护；②**样本 41 年（1985–2025，DHW 全部逐日）**，"多年稳定"指 41 年未达警戒，但**历史记录不等于未来情景**；③**5km 格点 ≠ 礁点**，只能给"哪片海"；④**不是投放效果评估** —— 项目**没有投放后存活率数据**，"效果好"三个字不能写；⑤西缘格点 DHW 异常偏高（见 §9.9 #40），引用前须实地核实 |

### 4.3 **语法检查不要用退出码猜**

PowerShell 下 `node --check x.js` 的 `$LASTEXITCODE` 会误判。正确方式：
```powershell
$p = Start-Process node -ArgumentList "--check","x.js" -NoNewWindow -Wait -PassThru `
     -RedirectStandardError "$env:TEMP\e.txt" -RedirectStandardOutput "$env:TEMP\o.txt"
if($p.ExitCode -eq 0){ "OK" } else { Get-Content "$env:TEMP\e.txt" }
```
Python 侧用 `python -c "import ast; ast.parse(open('x.py',encoding='utf-8').read())"`。

## 7.3 训练配置（两轮：先 640 从零，再 896 高分辨率微调）

| 轮次 | 起点 | imgsz | batch | epochs | 优化器 | 结果 |
|---|---|---|---|---|---|---|
| **R0** | COCO `yolov9c.pt` | 640 | 8 | 50（patience 15）| auto（AdamW）| mAP@0.5 **0.3864**（640，同口径复评）|
| **R1** | **R0 的 best.pt** | **896** | 4 | 30（patience 10）| AdamW `lr0=0.0015` | mAP@0.5 **0.4217** |

**为什么加第二轮**（先有证据再动手，而不是拍脑袋加轮数）：
1. R0 的曲线在 **epoch 15 就到 0.35、之后一直在 0.33–0.39 之间震荡**（epoch 45 才偶然取到 0.3858，即旧标签下的最佳）——
   说明**不是在"训不够"，而是已到 640 分辨率的天花板**。
2. 于是先做**推理分辨率扫描**（同一 R0 权重只改推理长边；**标签剔除蛤蜊后同口径复评**）：
   `imgsz 640→0.3864 / 896→0.4034 / 1024→0.4061`。
   分辨率一提就涨，**证实瓶颈是分辨率**，所以 R1 直接在 896 上微调。
3. R1 之后再扫：`640→0.3952 / 800→0.4156 / 896→0.4217 / 1024→0.4224 / 1152→0.4202` ——
   **896 与 1024 已在噪声内（差 0.0007）**，说明微调把分辨率缺口补齐了，故服务取 **896**（延迟更低）。

**⚠️ 训练前必须停服**：R0 第二轮实测踩过——服务与训练同占一块 8 GB 卡时（7889/8151 MiB），
训练从 **1.2 it/s 掉到 0.18 it/s（慢 6 倍）**且**不报 OOM**，极易被误判成"这个配置就是慢"。
停服后立刻回到 1.2 it/s。详见 §9.6 #31。

| 耗时 | R0 **146** 分钟 + R1 **156** 分钟 |
| 一键复现 | `python train_yolo_coral.py --model best_640r0.pt --imgsz 896 --batch 4 --epochs 30 --optimizer AdamW --lr0 0.0015 --force --name coral_yolov9c_896` |

## 7.6 局限（引用计数结论时**必须一并引用**）

| 局限 | 说明 |
|---|---|
| **真值是自动标注** | 由语义掩膜连通域导出，**非人工实例标注**；因此 mAP 是「与该方法生成的真值的一致程度」，不能等同于人工标准下的实例检测精度 |
| **同类相邻个体会合并** | 两个紧贴的同类珊瑚在掩膜里是同一个连通域 → 算 1 个，**计数系统性偏少** |
| **只有一类** | 不区分属 / 形态 / 健康状态；属与白化仍由 Model A/B 给出，两者互不替代 |
| **阈值敏感** | 计数依赖 `conf`（服务默认 **0.20**，使总量偏差 +2.3%）/ `iou=0.5`；换阈值须重算，见 7.4 ③ |
| **跨域未知** | 训练与验证都来自 Coralscapes（以红海为主）；**仙本那/印太真实照片未做实例级人工核验**，跨域计数准确性未知（与白化在印太域召回偏低属同类风险）|
| **无人工基线** | 与属级识别同样无法回答「模型达到什么水平」，是项目的永久局限 |

### ⚠️ 三年样本 vs 41 年样本：结论被推翻（**这是本节最重要的教训**）

用同样口径分别跑 3 年与 41 年，结果**性质完全不同**：

| | 3 年（2023–2025） | 41 年（1985–2025） |
|---|---|---|
| "不建议投放"格点 | **32 个"年年达警戒"** | **35 个**（按"≥3 次严重档事件"）|
| 最高警戒频率 | 100% | **17%**（最高 7/41 年）|
| 结论 | "西缘 32 格危险" | 危险是**事件性**的，不是常态；**没有任何格点半数年份达警戒** |

**三个必须记住的点**：
1. **2023–2025 恰好是一个偏暖窗口**（2024 为极端年）→ 只用这三年会把"偶发事件"误读成"年年发生"；
   凡是"频率/稳定性"类结论，**样本年数不足时不要下**（气候态 ≥10 年，最好 ≥30 年）。
2. 41 年数据下**严重档事件（DHW≥8）次数**才是有效区分信号：394 格从未出现、150 格 1–3 次；

   改为「相对本格点峰值频率 ≥50%」取季节窗口 → 得到 **5–8 月** 的紧凑窗口。

**外部一致性校验（可写进答辩）**：核心区（4.425N/118.775E）41 年中的警戒年份为
**2016 / 2020 / 2024**，与全球公认的三次大规模珊瑚白化事件年份吻合 —— 这是数据链路正确性的旁证。

## 9.13 为什么"每次识别都是白化警报一级"（第八轮，2026-10-11）

**现象**：小程序每次识别，环境卡片都显示同一个等级（一级）。

**根因（不是模型错，是每次都在问同一个问题）**：

| 项 | 值 | 位置 |
|---|---|---|
| 点位 | `lat 4.4, lon 118.8`（仙本那核心礁区）**写死** | `blue_coral/utils/config.js` 的 `DEFAULT_SITE` |
| 年份 | **`2024` 写死** | 同文件的 `DEFAULT_YEAR` |

同一格点不同年份的真实差异（官方 CRW_BAA 产品）：

| 年份 | DHW 峰值 | BAA 等级 | DHW≥4 天数 |
|---|---|---|---|
| 2023 | 1.68 | 2「白化警告」 | 0 |
| **2024（原先写死）** | **5.42** | **3「白化警报一级」** | **58** |
| 2025 | 2.69 | 2「白化警告」 | 0 |

而且该格点 **41 年（1985–2025）里只有 3 年达过警戒：2016 / 2020 / 2024**（占 7%）——
即"每次都固定问 41 年里最热的三年之一，还固定问那三年里最热的一年"，结论当然不变。

**已修（A+B）**：
- **A**：`DEFAULT_YEAR: null` → 由服务端取**最新可用年份**（实测返回 2025 → 「白化警告」），
  以后有新年份数据自动前进；卡片副标题改为「{{year}} 年**年度等级（非实时）**」，
  明确这是年度 BAA、不是实时状态。

  「历史热压力：近 41 年 3 年达警戒（2016、2020、2024）」+「建议避开：4、5、6、7 月」。

  （5.42 应为一级）→ 演示值改为与真实 2025 年一致的数值，并补 `deployment` 演示块。

## 9.15 P4 第一步：白化事件年表 × 41 年 DHW 序列（第十轮，2026-10-11）

**做法**：P4 此前卡在"先验证数据前提"。本轮把前提查清并做了**事件级**一致性核对。

**数据前提核查（三条时间来源）**

| 来源 | 结果 |
|---|---|
| 照片 EXIF（`DateTimeOriginal`） | **0%**——所有图集（semporna_photos / iNat / yolo_coral / bleaching_new / coral_indo）都已被剥掉 EXIF |

| Reef Check Malaysia 报告 | ✅ **有调查年份 + 白化事件叙述**（7 份 PDF，含专门的 `2024CoralBleachingImpactReportMalaysia.pdf`）|

→ 结论：**照片级时序不可行**（无 EXIF），但**事件级时序可行**（实地报告年表 + 我们的 41 年 DHW）。

**产物**：`scripts/p4_event_timeline.py` → `reports/p4_event_timeline.json`；汇总报告新增 §5.7。

**结果（我们的序列 vs 报告记载的事件年）**

| 报告记载 | 我们序列的排名 | 一致性 |
|---|---|---|
| **2024** 沙巴区域热压力历史最高 | **区域均值/最大均第 1**（5.37 / 14.87，50.0% 格点警戒）| ✅ |
| **2020** 沙巴东部显著白化 | **第 2**（5.27 / 14.08，62.3%）| ✅ |
| **2016** 2014–2017 全球事件期内 | **第 3**（3.64 / 9.85，43.2%）| ✅ |
| 2019 白化（**半岛**马来西亚）| 第 17（仅 1.8% 格点警戒）| ✅ **恰好印证"不是沙巴"** |
| 1998 全球事件（南海/半岛）| 无警戒格点 | ✅ 与"对沙巴影响有限"一致 |
| 2010 马来西亚大规模白化 | 均值第 6 / 最大第 5（13.8%）| 🟡 报告称 2010 是"2024 之前的记录年"，我们的网格里 2016/2020 更高 —— **报告口径是站点级，与区域统计不同** |

**定量锚点**：报告称"2024 比 2010 高约 5 °C-weeks（站点级）"；我们区域最大差 **+8.01**、区域均值差 **+2.66** —— 量级一致，口径不同。

**副产物发现**：**1986 年**在我们序列里均值排第 4（38.6% 格点警戒），而马来西亚的系统性监测 **2007 年才开始** → 属"监测开始前的高热压力年"，可列为**待考事件**（1986–87 为强 El Niño 年，方向合理）。

⚠️ **口径限制（必须随结论说明）**：报告监测站分布在沙巴与半岛多地，我们的网格只覆盖仙本那周边；事件年表来自报告正文叙述（非标准化数据集），**n=8 事件级，不做显著性检验**；1985–2022 目前仍为每 5 天抽稀（逐日补全进行中）。

**第二步可行性判定（已完成，结论：不可行）**：`scripts/p4_step2_feasibility.py` → `reports/p4_step2_feasibility.json`

| 前提 | 实测 |
|---|---|
| 观察日期 | ✅ **100% 覆盖**（`observed_on`，iNat 各清单跨 1980–2026）|
| 坐标 | ✅ 100% 有 `lat/lon`（可匹配 5km 格点）|
| 本地图片可匹配 | 🟡 文件名前缀 = `obs_id`，但**本地只覆盖部分记录**（见下方数据完整性）|
| **可靠且带日期的白化标签** | ❌ **不具备** |

**为什么不可行（三条硬理由）**：
1. **白化标签来源不可靠**：**部署模型 `bleaching_all`** 在跨域印太留出（`test_ip`, n=176）上
   准确率 **0.8295 < 多数类基线 0.8523**、bleached 召回仅 **0.4231**；另一模型 `bleaching_ip` 为 0.8523
   （= 基线），二者差异 **McNemar p=0.424 不显著** → 用它给 iNat 照片打白化标签＝测量模型偏差而非现实；
   iNat 缓存元数据里也没有 iNat 自身的白化注释字段（只有 label/url/license/attribution/lat/lon/observed_on/taxon_name）
2. **采样非平稳**：iNat 观察量逐年暴增（2000→2026 约两个量级），年度"白化率"必然与"谁在什么时候上传"混淆
3. **观察者自选择**：爱好者更愿意拍好看的珊瑚，白化照片入样概率未知

**会解除阻塞的条件**：拿到**带日期的白化标注**（专家标注，或合作方提供带日期的白化调查记录）；或先把白化分类器在印太域的 bleached 召回做到可用（需印尼/马来域标注图像）。

### 数据完整性：本地测试图缺失（本轮发现，重要）

| 项 | 数值 |
|---|---|
| 属级评估协议 `protocol_species_ip_test.json` | **n_samples = 1116**（逐类 n 求和 = 1116，自洽）|
| 本地 `data/inat_dataset/images/test/` 现有图片 | **487 张**（34 类**每类都少于**协议 n）|

→ **含义**：当初的 1116 张评估是有效的（当时图在），但**现在重跑属级评估只会用到 487 张，指标会变**。
**重跑前需重新下载测试集**（`dl_inat_genus.py` 之类脚本；清单 `data/inat_dataset/genus_test.json` 仍在，含 url 字段可重下）。

# §10 评估口径约定（**必须遵守，否则数字不可比**）

| 约定 | 值 |
|---|---|
| **推理分辨率** | **1024px**（模型原生；512px 会让 mIoU 腰斩）|

| **置信区间** | **聚类自助 CI**（按 observation 聚类），非朴素 bootstrap |
| **不平衡数据** | 必须同时报**多数类基线 + 平衡准确率 + Cohen's kappa** |
| **混淆矩阵轴向** | 全项目统一 `conf[gt, pred]` |
| **数据泄漏** | 已用 pHash 审计；报告需注明是否剔除 |
| **参考基准** | 活珊瑚覆盖率参考满值 **0.40**（= RCM 区域平均 39.56%）|
| **个体计数主指标** | Coralscapes 官方 validation split 的 **mAP@0.5**（服务与验收同为 imgsz **896**；mAP 与阈值无关）|
| **计数真值口径** | 掩膜**同类 8 邻域连通域**外接矩形（面积 ≥200 px）—— **自动标注**，非人工实例标注，引用时必须声明 |
| **计数泄漏隔离** | train / val **按站点隔离**（22 站 vs 3 站），与属级「地理隔离」口径同源 |
| **计数工作点** | 服务默认 `conf=0.20`（总量偏差 +2.3%）；`iou=0.5`；**换阈值必须重算计数指标** |
| **计数超参** | R0：640 / batch 8 / 50 epochs；**R1：896 / batch 4 / 30 epochs（微调）**；8 GB 显存为上限 |
| **气候数据空间范围** | 仅 **4.025–5.025°N × 118.025–119.525°E**（21×31）；**网格外必须报缺数据（ok=false），不得取最近格点** |

| **投放时间窗口径** | 风险月 = DHW≥4 ∪ HotSpot≥1（取并集，更保守）；**只报热压力维度**、**41 年样本（1985–2025，DHW 逐日）**、5km 格点；**不得表述为投放效果**（无存活率数据）|
