**关键耦合**：
- 小程序 ↔ `serve_fusion.py`（**不是** 已弃用的 `serve.py`）
- Skill ↔ `serve_fusion.py`（端点为 `/analyze`、`/climate`、`/priority`）
- `restoration_priority` 依赖 `climate_context` 与 `restoration_simulation`

**四个模型分别回答不同问题**（易混）：

| 模型 | 回答 | 注意 |
|---|---|---|
| Model A（分割）| 各类**像素占比** | 其白化像素跨域 **AUC 0.46 无效** |
| Model B 属分类 | 这是什么**珊瑚属** | 只在分割出的珊瑚主体上判 |
| Model B 白化分类 | 整图**白化状态** | **白化结论以它为准** |
| **Model C 个体检测** | **有多少个珊瑚个体、在哪** | **P3 附加能力**；与上面三者互不替代，缺失也不影响主结果 |

> ⚠️ 另有**两个不是"模型"的插件**（易被漏掉，2026-10-10 已发生一次误读）：
> **环境数据插件**（NOAA 热压力）与**综合研判插件**（修复优先级 + 保育报告 + 10 年模拟）。

# §1.6 能力与交付边界（对外表述的**唯一权威版本**）

> 用途：对外材料/答辩/汇报要讲"现在能交付什么"时，**以本节为准**，避免漏项或说过满。
> 每条都给出证据文件；"不报准确率"≠"做不出来"，两者必须区分开。

## 能稳定交付（有实测背书）

| 能力 | 指标 | 证据 |
|---|---|---|
| 礁区覆盖率（6 功能群）| 分割 mIoU **0.5484**；星地 **39.71% vs 39.56%**（区域尺度）| `reports/segmentation_miou_1024.json`、`reports/segment_validation.json` |
| 珊瑚属（34 属）| Top-1 **86.12%**（剔泄漏，聚类 CI 83.33–88.88）；拒识 0.9 → 自动化 70.3% / 97.07% | `reports/protocol_species_ip_test_clean.json`、`reports/error_attribution_species_ip_test.json` |
| 整图白化状态（健康/白化/死亡）| 第三方独立集 **98.21%**（召回 96.77%）| `reports/new_bleaching_bleaching_all_test_clean168.json` |
| 珊瑚个体计数 + 位置（P3 附加）| mAP@0.5 **0.4217**；conf=0.20 时总量偏差 **+2.3%** | `reports/yolo_coral_metrics.json`、`reports/yolo_coral_count_thresholds.json` |
| 拍摄条件闸门 | 降质集 5/5；阈值见 `capture_quality_thresholds.json` | `reports/capture_quality_thresholds.json` |
| **环境数据插件**（NOAA DHW/BAA/HotSpot/SSTA/SST）| 官方产品（BAA 优先取 CRW_BAA 产品），5 变量 / 2023–2025 / 21×31 格点；**限网格内** | `data/noaa/climate_index.json`、`GET /climate` |
| **综合研判插件**（修复优先级 + 保育报告 + 10 年模拟）| **可用、已接入前端**；**不报准确率**（原因见下）| `scripts/restoration_priority.py`、`POST /priority`、`/analyze` 带 lat/lon 自动附带；实测 priority 53.6 / 三级·可观察 / 恢复 64.5 / 紧迫 40.3 / 苗投放 49.1 + 1047 字报告 + 3 个模拟情景 |

**为什么"修复优先级"没有准确率——是任务性质，不是技术没做到**：
"哪个点位该优先修复"是**价值判断，不存在客观 ground truth**，因此本项目**主动选择**
只报评分构成、权重与依据（可解释），不报准确率。这与"印太域白化做不出来"完全不同：
后者是**能力缺口**（召回仅 42.31%），前者是**指标口径选择**。

## 有条件交付（引用时必须带限定）

| 能力 | 限定 |
|---|---|
| 覆盖率 | 仅**区域尺度**；站点级不成立（3 站点 15 张，偏差 **+11.7 pt**，r = **−0.56**）|
| 覆盖率/白化 | 深度边界：≤8m 误差 ≤3 pt；**≥15m 完全失效**（−39.5 pt）|
| 属级 | 只到**属**不到**种**；长尾属弱；受 iNaturalist 采样偏置影响 |
| 个体计数 | 真值为**掩膜连通域自动标注**，紧贴个体合并 → 偏少；**跨域（仙本那实拍）未验证** |
| 拍摄条件闸门 | 阈值在**合成降质**集上标定；**真实劣化照片（P2）未验证** |
| 修复优先级 | **权重未经真实修复成效标定**；单点代表点位；未纳入社会经济因子 |
| **环境数据（气候背景）** | ①**只覆盖仙本那网格** 4.025–5.025°N × 118.025–119.525°E —— **网格外直接返回 `ok=false`**，不给"最近格点"的值（旧版会静默取，实测查深圳会报出仙本那的"严重热应激"，已修，见 §9.8 #38）；②**2023–2025 历史值，不是实时预警**，不能回答"现在热压力多少"；③**站点级不成立**（卫星 5km ≠ 站点，仅事件级一致，n=4）；④引用"DHW 峰值"**必须标空间单位**（查询格点 5.42 / 核心区 10.03 / 网格最大 14.87）|
| **综合研判 + 10 年模拟** | 规则启发式：**不报准确率是口径选择，不是能力缺失**；但**模拟为示意性推演**，未做本地参数标定，不得当预测用；气候维度缺失时会如实标 `climateAvailable=false` 且不参与打分 |

## 明确不能交付

| 项 | 证据 |
|---|---|
| **印太域白化判定** | 召回 **42.31%**；决策规则修正后 34.6–57.7% 且精度掉到 27% → 需域自适应 |
| 物种级识别 | 无物种模型（仅 34 属）|
| **逐个体**健康状态 | 白化是**整图级**结论 |
| 站点级优劣排序 | 见上，偏差 +11.7 pt、负相关 |
| "达到什么水平"的结论 | 无人类基线（永久局限）|

### 4.3 **语法检查不要用退出码猜**

PowerShell 下 `node --check x.js` 的 `$LASTEXITCODE` 会误判。正确方式：
```powershell
$p = Start-Process node -ArgumentList "--check","x.js" -NoNewWindow -Wait -PassThru `
     -RedirectStandardError "$env:TEMP\e.txt" -RedirectStandardOutput "$env:TEMP\o.txt"
if($p.ExitCode -eq 0){ "OK" } else { Get-Content "$env:TEMP\e.txt" }
```
Python 侧用 `python -c "import ast; ast.parse(open('x.py',encoding='utf-8').read())"`。

## 7.3 训练配置（两轮：先 640 从零，再 896 高分辨率微调）

| 轮次 | 起点 | imgsz | batch | epochs | 优化器 | 结果 |
|---|---|---|---|---|---|---|
| **R0** | COCO `yolov9c.pt` | 640 | 8 | 50（patience 15）| auto（AdamW）| mAP@0.5 **0.3864**（640，同口径复评）|
| **R1** | **R0 的 best.pt** | **896** | 4 | 30（patience 10）| AdamW `lr0=0.0015` | mAP@0.5 **0.4217** |

**为什么加第二轮**（先有证据再动手，而不是拍脑袋加轮数）：
1. R0 的曲线在 **epoch 15 就到 0.35、之后一直在 0.33–0.39 之间震荡**（epoch 45 才偶然取到 0.3858，即旧标签下的最佳）——
   说明**不是在"训不够"，而是已到 640 分辨率的天花板**。
2. 于是先做**推理分辨率扫描**（同一 R0 权重只改推理长边；**标签剔除蛤蜊后同口径复评**）：
   `imgsz 640→0.3864 / 896→0.4034 / 1024→0.4061`。
   分辨率一提就涨，**证实瓶颈是分辨率**，所以 R1 直接在 896 上微调。
3. R1 之后再扫：`640→0.3952 / 800→0.4156 / 896→0.4217 / 1024→0.4224 / 1152→0.4202` ——
   **896 与 1024 已在噪声内（差 0.0007）**，说明微调把分辨率缺口补齐了，故服务取 **896**（延迟更低）。

**⚠️ 训练前必须停服**：R0 第二轮实测踩过——服务与训练同占一块 8 GB 卡时（7889/8151 MiB），
训练从 **1.2 it/s 掉到 0.18 it/s（慢 6 倍）**且**不报 OOM**，极易被误判成"这个配置就是慢"。
停服后立刻回到 1.2 it/s。详见 §9.6 #31。

| 硬件 | RTX 5060 Laptop **8 GB**（896/batch4 训练峰值约 5.3 GB，未 OOM）|
| 耗时 | R0 **146** 分钟 + R1 **156** 分钟 |
| 一键复现 | `python train_yolo_coral.py --model best_640r0.pt --imgsz 896 --batch 4 --epochs 30 --optimizer AdamW --lr0 0.0015 --force --name coral_yolov9c_896` |

## 7.6 局限（引用计数结论时**必须一并引用**）

| 局限 | 说明 |
|---|---|
| **真值是自动标注** | 由语义掩膜连通域导出，**非人工实例标注**；因此 mAP 是「与该方法生成的真值的一致程度」，不能等同于人工标准下的实例检测精度 |
| **同类相邻个体会合并** | 两个紧贴的同类珊瑚在掩膜里是同一个连通域 → 算 1 个，**计数系统性偏少** |
| **只有一类** | 不区分属 / 形态 / 健康状态；属与白化仍由 Model A/B 给出，两者互不替代 |
| **阈值敏感** | 计数依赖 `conf`（服务默认 **0.20**，使总量偏差 +2.3%）/ `iou=0.5`；换阈值须重算，见 7.4 ③ |
| **跨域未知** | 训练与验证都来自 Coralscapes（以红海为主）；**仙本那/印太真实照片未做实例级人工核验**，跨域计数准确性未知（与白化在印太域召回偏低属同类风险）|
| **无人工基线** | 与属级识别同样无法回答「模型达到什么水平」，是项目的永久局限 |

# §10 评估口径约定（**必须遵守，否则数字不可比**）

| 约定 | 值 |
|---|---|
| **推理分辨率** | **1024px**（模型原生；512px 会让 mIoU 腰斩）|
| **属级主指标** | 仙本那留出集 Top-1（地理隔离）|
| **置信区间** | **聚类自助 CI**（按 observation 聚类），非朴素 bootstrap |
| **不平衡数据** | 必须同时报**多数类基线 + 平衡准确率 + Cohen's kappa** |
| **混淆矩阵轴向** | 全项目统一 `conf[gt, pred]` |
| **数据泄漏** | 已用 pHash 审计；报告需注明是否剔除 |
| **参考基准** | 活珊瑚覆盖率参考满值 **0.40**（= RCM 区域平均 39.56%）|
| **个体计数主指标** | Coralscapes 官方 validation split 的 **mAP@0.5**（服务与验收同为 imgsz **896**；mAP 与阈值无关）|
| **计数真值口径** | 掩膜**同类 8 邻域连通域**外接矩形（面积 ≥200 px）—— **自动标注**，非人工实例标注，引用时必须声明 |
| **计数泄漏隔离** | train / val **按站点隔离**（22 站 vs 3 站），与属级「地理隔离」口径同源 |
| **计数工作点** | 服务默认 `conf=0.20`（总量偏差 +2.3%）；`iou=0.5`；**换阈值必须重算计数指标** |
| **计数超参** | R0：640 / batch 8 / 50 epochs；**R1：896 / batch 4 / 30 epochs（微调）**；8 GB 显存为上限 |
| **气候数据空间范围** | 仅 **4.025–5.025°N × 118.025–119.525°E**（21×31）；**网格外必须报缺数据（ok=false），不得取最近格点** |
| **气候数据时效** | **2023–2025 历史值**，不是实时预警；引用"DHW 峰值"必须标明空间单位（查询格点 / 核心区 / 网格最大）|
| **气候数据来源** | BAA **优先官方 CRW_BAA 产品**；缺值才用已校准阈值兜底并标 `baaEstimated` |
