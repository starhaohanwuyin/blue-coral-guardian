# 小程序「礁区识别 + 白化程度评估」启动与验证指南

> 目标：确认小程序能正常识别**珊瑚覆盖率**与**白化程度**。
> 一键自检：`python ai-service/scripts/e2e_check.py`（实测 **25/25** 通过）

---

## 一、启动（每次演示前做一遍）

```powershell
# 1) 启动推理服务（首次加载模型约 40–60 秒）
cd ai-service/scripts
python serve_fusion.py --port 8000
```

看到下面这行即为就绪：
```
INFO:     Uvicorn running on http://0.0.0.0:8000
```

```powershell
# 2) 验证服务
curl http://127.0.0.1:8000/health
```

期望输出（关键字段）：
```json
{
  "status": "ok",
  "segmentation": "loaded",
  "species": "loaded",
  "segModel": "segformer_coralscapes",
  "segCalibrated": true,      ← 必须为 true（否则覆盖率会偏高约 13 个百分点）
  "categories": 40
}
```

```powershell
# 3) 运行端到端自检
python e2e_check.py
```

## 二、小程序端

1. 微信开发者工具打开 `blue_coral` 项目
2. 进入 **AI 识别** 页（底部第 4 个 tab）
3. 点「上传水下礁区照片」选择图片 → 自动识别
4. 页面展示：
   - **礁区覆盖评估**：活珊瑚 / 白化珊瑚 / 死亡珊瑚 / 藻类覆盖 / 沙砾底质（百分比条）
   - **珊瑚总覆盖** 与 **占珊瑚的白化比例**
   - **主要珊瑚属**（在分割出的珊瑚区域上识别）
   - **拍摄条件自检**：超出适用边界时置顶红色警示

> 后端地址在 `miniprogram/utils/config.js` 的 `CORAL_API`（默认 `http://127.0.0.1:8000`），
> `USE_REAL_AI: true` 表示调用真实服务。

## 三、无图片时的自动化验证

小程序的 `wx.chooseMedia` 需要人工选图，无法脚本化。
为此服务提供了 `/sample` 接口，可用 `wx.downloadFile` 取到真实图片路径跑通完整链路：

```
http://127.0.0.1:8000/sample?set=semporna&index=0     # 仙本那健康礁区
http://127.0.0.1:8000/sample?set=bleached&index=8     # 已知含白化（→ 白化约 10.6%）
http://127.0.0.1:8000/sample?set=healthy&index=0      # 健康样本
```

> P3 给 e2e_check 增加了 4 项「珊瑚个体计数」检查（计数模型未训练时会跳过并回到 15/15）。

| 检查项 | 结果 |
|---|---|
| 服务在线 / 分割已加载 / **权重已校准** / 属分类已加载 | ✅ |
| 仙本那照片 #0 → 珊瑚总覆盖 **51.2%**（0.28s） | ✅ |
| 仙本那照片 #3 → 珊瑚总覆盖 **42.8%**（0.25s） | ✅ |
| 仙本那照片 #7 → 珊瑚总覆盖 **86.2%**（0.19s） | ✅ |
| **白化检出** → 白化 **10.56%**，占珊瑚 **14.2%** | ✅ |
| **属级识别** → Acropora 54% / Turbinaria 24% / Duncanopsammia 5% | ✅ |
| 拍摄条件自检 → good | ✅ |
| **超边界识别** → 20m 降质照片判为 poor（对比度 0.0052） | ✅ |
| **P3 计数**：模型已加载 / `/analyze` 新增 `coralCount`（15 个，46.8ms）/ 既有字段齐备 / `POST /count` 可用 | ✅ |
| **投放时间窗档案**：可按坐标查（逐年峰值 + 建议避开月份）/ 覆盖闸门对网格外坐标返回 `ok=false` | ✅ |
| **环境卡片 A+B 改进**：默认年份改为「最新可用年」（2025，等级「白化警告」）/ 卡片标注「年度等级（非实时）」/ 新增两行「历史热压力（41 年中 3 年达警戒：2016、2020、2024）」与「建议避开（4、5、6、7 月）」| ✅ |

> **为什么之前每次都是「白化警报一级」**：小程序把点位（4.4N/118.8E）与年份（2024）都写死了，
> 而 2024 正是该点位 41 年里最热的 3 年之一（DHW 峰值 5.42、58 天 ≥4）→ BAA=3。
> 现改为 `DEFAULT_YEAR: null`（由服务端取最新可用年），同一格点变为 2025 年的「白化警告」（DHW 2.69）；
> 并新增「历史热压力 / 建议避开」两行，避免把单年等级误读为常态。详见 `docs/项目交接与续接指引.md` §9.13。

**链路一致性验证**：小程序返回的 18.3% / 0% / 30.9% / 50.8%
与直接调用模型得到的 18.31% / 0% / 30.87% / 50.79% **完全一致**。

## 五、输出字段说明

| 字段 | 含义 |
|---|---|
| `cover.alivePct` | 活珊瑚覆盖百分比 |
| `cover.bleachedPct` | **白化珊瑚百分比** |
| `cover.deadPct` | 死亡珊瑚百分比 |
| `cover.algaePct` | 藻类覆盖百分比 |
| `cover.substratePct` | 沙/碎石/底质百分比 |
| `cover.coralTotalPct` | 珊瑚总覆盖（活+白化+死亡） |
| `cover.bleachingShareOfCoral` | **白化占珊瑚的比例**（>10% 时页面给出警示） |
| `coralRegion.top[]` | 主要珊瑚属及置信度（<40% 时不给结论） |
| `captureQuality` | 拍摄条件：good / warn / poor；`usable=false` 时覆盖率不可信 |

## 六、适用边界（务必遵守）

| 拍摄条件 | 表现 |
|---|---|
| ≤3m | 覆盖率误差约 −1.7% |
| **8m（典型潜水）** | **误差约 −2.2%** ✅ 推荐 |
| 15m 以上 / 水体浑浊 | **显著失效** ❌ |

**建议：拍摄深度 ≤10m 或使用补光灯。** 服务会自动检测并提示超边界的照片。

## 七、常见问题

**Q: 页面提示"无法连接评估服务"？**
A: 服务没启动，或端口不对。执行 `python serve_fusion.py --port 8000`，
并确认 `utils/config.js` 的 `CORAL_API` 与端口一致。

**Q: 覆盖率明显偏高？**
A: 检查 `/health` 的 `segCalibrated` 是否为 `true`。
若为 `false`，说明加载了未校准的实验权重（会高估约 13 个百分点）。

**Q: 白化显示 0%，但这张图看着有白化？**
A: 两种可能：① 该图白化像素确实极少；② 拍摄条件超出边界（看页面顶部是否红色警示）。
另外数据集中部分"白化"标注为伪标签，存在噪声——这是已知短板，
详见 `docs/答辩要点.md` 第四节。
