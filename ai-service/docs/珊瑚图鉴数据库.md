# 珊瑚图鉴数据库（科普页「珊瑚种类」的数据源）

> 一句话：科普页和「全部种类」页的种类**不写死在代码里**，而是读一个 SQLite 图鉴库；
> 你可以打开后台页面直接上传、编辑、导出，加多少条都行。

---

## 一、数据怎么流

```
tools/gen_coral_catalog.py  ──►  data/corals/coral_species.json    种子数据（入 git）
                            └─►  data/corals/corals.db            首次启动自动建库灌种子（不入 git）

/admin.html 上传 / POST /corals/import  ──►  corals.db   即写即生效
小程序 · 网页版  GET /corals            ◄──  corals.db   页面刷新即见
```

- 当前种子：**原版精编 12 条**（6 条精选 + 6 条；配图沿用原来的实物图）。
  > 2026-10 已回退：之前那套 300+ 条自动扩展表 + 自动生成示意图**已删除**，页面恢复成原来的种类与实物图。
- 连不上服务时，页面自动退回 `miniprogram/utils/mock.js` 里的 24 条演示数据（不会白屏）。

## 二、怎么加自己的种类（推荐：后台页面）

1. 启动服务：`cd ai-service/scripts && python serve_fusion.py --host 0.0.0.0 --port 8000`
2. 浏览器打开 **`http://127.0.0.1:8000/admin.html`**
3. 三种加法：
   - **批量上传**：点「下载 CSV 模板」→ 用 Excel 填好 → 拖回页面（或直接传 JSON）
   - **单条新增**：页面下半部分的表单，填完点「保存条目」
   - **改已有条目**：把导出的 JSON 改好再传回来（勾选「覆盖同 id 条目」）
4. 传完刷新小程序/网页版即可看到。手机连同一 Wi-Fi 时，把 `127.0.0.1` 换成电脑局域网 IP 也能开这个后台。

> 「精选」打勾的条目会出现在科普页顶部横滑和首页展示位（建议 8–12 条）。

### CSV / TSV 表头（中英文都认）

| 列 | 必填 | 说明 |
|---|---|---|
| 中文名 | ✅ | 例如「强壮鹿角珊瑚」 |
| 拉丁名 | | 例如 `Acropora valida`；id 会由它自动生成 |
| 属 / 属中文名 | | 例如 `Acropora` / 「鹿角珊瑚属」 |
| 科 | | 例如「鹿角珊瑚科 Acroporidae」 |
| 级别 | | `genus`（属级）或 `species`（种级） |
| 类群 | | 造礁石珊瑚 / 非造礁石珊瑚 / 软珊瑚 / 水螅珊瑚 / 柳珊瑚 |
| 分布 | | 例如「印度-太平洋」 |
| 描述 | | 形态、生态位、耐热性等 |
| 白化敏感度 | | 高 / 中 / 低 |
| 造礁 / AI可识别 / 精选 | | 是/否（或 true/false、1/0） |
| 配图 / 标签 / 来源 | | **`配图` = 实物图键**（`coral1`…`tech5`、`camp`，对应小程序 `utils/mock.js` 的 IMG）；**`图片URL` = 自己照片的 http(s) 地址**（有就优先用）；标签逗号分隔 |

> 只写「中文名」也能入库，其余留空即可；重复上传同一个 id 会覆盖（除非取消勾选覆盖）。

## 三、命令行（批量/自动化）

```bash
# 改完种子表后重新生成 JSON
python tools/gen_coral_catalog.py

# 看统计
python scripts/coral_catalog.py --stats

# 导入自己的 CSV/JSON（--no-overwrite = 只补缺失项）
python scripts/coral_catalog.py --import my_corals.csv

# 导出全部（改完再传回来）
python scripts/coral_catalog.py --export backup.json

# 用种子补齐缺失条目（不覆盖你改过的）
python scripts/coral_catalog.py --reload
```

## 四、HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/corals` | 列表。参数：`q` 关键词、`genus` 属、`level`、`featured`、`limit`、`offset`、`order` |
| GET | `/corals/stats` | 统计（总数/属数/科数/分组/属清单） |
| GET | `/corals/{id}` | 单条 |
| POST | `/corals` | 新增/覆盖一条（JSON body，字段名中英文都认） |
| PUT | `/corals/{id}` | 局部更新 |
| DELETE | `/corals/{id}` | 删除 |
| POST | `/corals/import` | 上传文件批量导入（multipart，字段名 `file`） |
| POST | `/corals/seed` | 用仓库种子补齐缺失项 |
| GET | `/corals/export` | 导出全部 JSON |

写着「上传/改/删」的接口，在服务端设了 `CORAL_API_TOKEN` 时需要带 `X-API-Token`（后台页面右上角可填）。

```bash
# 例子：查「鹿角」相关前 5 条
curl "http://127.0.0.1:8000/corals?q=鹿角&limit=5"

# 例子：上传一个 CSV
curl -F "file=@my_corals.csv" http://127.0.0.1:8000/corals/import
```

## 五、备份与迁移

- 图鉴库 = 单个文件 `ai-service/data/corals/corals.db`，拷走即备份；换机器拷回来即可。
- 种子数据在 `data/corals/coral_species.json`（入 git），`POST /corals/seed` 可随时补齐。
- 想彻底重置：删掉 `corals.db`，重启服务会自动按种子重建。

## 六、数据口径（重要，别写错）

- `level=genus` 的条目是**属级**通用特征描述，可靠；
- `level=species` 的条目是**属级特征 + 常见种名**，种级细节可能不完整 —— 每条都带 `source`
  字段，页面上不会宣称「权威鉴定」。要对外引用，请按上表补录核对后再改成你的来源。
- **不要和 AI 混淆**：AI 模型可识别的是 **34 个属**（`aiGenus=true`）；图鉴收录的是
  「几百条属/种条目」。页面上两处数字要分开说，别把图鉴条数写成识别准确率相关指标。

## 七、详情页字段与配图

点开任意一条种类（图鉴列表 / 科普页横滑都能点），进的是**珊瑚种类详情页**，内容分四大板块，
数据全部来自图鉴库的同一条记录：

| 板块 | 字段（数据库列名） |
|---|---|
| ✅ 基础档案 | `name` 中文名 · `alias` 别名 · `latin` 拉丁学名 · `taxonomy` 生物分类 · `protection` 保护等级（+`protectionNote` 口径说明）· `dist` 分布海域 · `group` 类群 · `genus` 属 |
| ✅ 形态识别 | `colonyForm` 群落形态 · `sizeCm` 成体尺寸 · `colorDesc` 外观颜色 · `idFeature` 简易辨识特征 |
| ✅ 生物习性 | `depthM` 栖息水深 · `tempSal` 适宜水温盐度 · `growthRate` 生长速度 · `symbiosis` 与虫黄藻共生特点 · `companions` 伴生生物 |
| ✅ 生存威胁 | `bleachingRisk` 白化敏感程度 · `threats` 主要致危因素 |

> 这些字段**按群落形态（`form`）给了属级通性默认值**，再由种子里的种级补充微调；
> 想换成自己核对的资料，直接用后台/CSV 覆盖同名条目即可（列名见第二节表格）。

### 配图：只用实物图

配图优先级（页面：列表缩略图、详情页大图都用同一张）：

1. **`imgUrl`**：条目自带照片的 http(s) 地址（自己上传的照片走这条）
2. **`imgKey`**：原来的实物图键（`coral1`…`tech5`、`camp` → 小程序 `utils/mock.js` 的 IMG；
   网页端构建时会本地化成 `/mp/assets/img/*.jpg`，离线可用）
3. 都没有 → 页面显示占位块（不会出现破图，也不会自动画一张示意图）

> 之前那版「按形态自动生成示意图」的功能已连同接口一起删除（`GET /corals/{id}/image.jpg` 已下线）。

要给某个种类换成自己的照片：后台「图片URL」填地址，或 CSV 的 `图片URL` 列填好再上传；
批量替换可先「导出全部 JSON」，改完再传回来。
