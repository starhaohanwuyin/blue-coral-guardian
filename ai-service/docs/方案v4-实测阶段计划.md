## 三、结构性新增：可恢复性设计（前几版最大的缺口）

**实测教训**：本次会话中 **至少 3 次**后台任务在空闲期被中断，
其中一次让我**误以为模型在印太域只有 6.25%**（实为 85.23%）。

**v4 强制要求：每个阶段必须幂等且可续跑。**

| 阶段 | 续跑机制 | 完成标志 |
|---|---|---|
| 元数据抓取 | 逐页落盘 + `done_boxes` 网格记录 | `data/inat/<name>.json` 存在 |
| 图片下载 | 跳过已存在文件 + `ATTRIBUTION.csv` | 各类目录张数 ≥ 阈值 |
| 模型训练 | 每轮存 `last.pt` + `--resume` | `reports/<task>/metrics.json` 存在 |
| 降质评估 | 结果 JSON 按 tag 分文件 | `reports/degradation_modelA_<tag>.json` |
| 自蒸馏 | **每轮**保存权重 | `weights/*_degradinv/config.json` |
| 自动链路 | 用**日志活跃度**判断进程存活（`wmic` 已在新版 Windows 移除） | `reports/chain.log` 出现"链路完成" |

**待补**：`resume_all.py` —— 一键检测当前状态并续跑所有未完成阶段。
