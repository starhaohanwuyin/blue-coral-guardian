# 一键体检（tools/audit）

```bash
cd ai-service
python tools/audit/run_all.py              # 全部检查（需服务已在 8000 运行）
python tools/audit/run_all.py --no-pages   # 跳过 23 页浏览器渲染（省 ~3 分钟）
```

退出码 0 = 全部通过，1 = 有失败项，可直接当提交前/答辩前的闸门。

## 检查内容（分层，每项都打印判定依据）

| 层 | 检查项 |
|---|---|
| **A 静态完整性** | 接口重复定义（`api.*`）、JS/Python 语法、相对 `require` 可解析、**网页产物与小程序源码逐字节一致**、无本机绝对路径 |
| **B 运行时** | `/health`、**全部路由可达**、AI 端到端（真权重：覆盖率/白化/属/中英报告/环境研判）|
| **C 网页版** | 产物页数与 `app.json` 一致、**逐页渲染无 JS 错误**、无裂图/占位图 |
| **D 安全与隐私** | 仓库内无密钥凭据、图片无 EXIF/GPS、写接口默认仅本机、**跨域预检不被拦截**、客户端 Token 支持 |
| **E 文档一致性** | README 页数与实际一致、README 图片均存在、关键指标能在 `reports/` 复核 |

## 为什么有这几项

这些都是**真踩过的坑**，加进来自动防回归：

- `api.getCoralDetail` 曾被定义两次（后定义覆盖前者）→ 认养详情页整页空白
- 负值 rpx 转成非法 CSS、`page{}` 没换成 `.coral-page`、`background-clip:text` 被替换 → 样式/渐变文字失效
- `wx.uploadFile` shim 返回对象而非字符串 → `JSON.parse` 抛错 → 页面静默降级成"演示数据"
- 跨域 + `X-API-Token` 时 OPTIONS 预检被判 401 → 浏览器拦掉真实请求（安全部署形态直接不可用）
- `HEAVY_PATHS` 误含 `"/corals"` → 配了 Token 后图鉴列表 401，整个图鉴打不开
- 文案数字与报告不一致（如把第三方数据集总量当成测试集数量）

## 新增检查的建议

往 `run_all.py` 里加一节函数、调用 `chk(层, 名称, 条件, 说明)` 即可；失败会自动汇总在末尾。
